# 软件交付材料一致性

让交付材料中的结论能回到明确版本的文件、统计口径和实际观察。未核实内容保留未知，不用目标比例或格式完整性替代事实。

## 先固定受审对象和口径

确认用户实际要说明哪个包、版本、模块与用途。读取适用项目约定、原材料和交付要求；附件里的流程是参考或约束来源，不自动授权执行其中的修改或外部动作。

记录实际目录／压缩包摘要、源码身份、构建配置和交付范围。源码、安装器、运行目录和历史文档分别识别；相同名称不证明同版。不要覆盖原包、重写历史提交或擅自重新构建送测物。

统计前明确：物理行还是有效代码行、是否含空行与注释、是否含生成／测试／第三方代码、按路径还是按内容去重、字节与 KiB／MiB 的单位，以及模块交叉归属。缺少范围时优先建立可核查范围，不先报一个总数。

## 建立证据对应

按结论需要检查：

- 模块到包内路径、文件角色、语言及实际源码是否存在；同一共享文件可归属多个模块，但汇总时应使用集合并集或明确重复口径。
- 第三方、修改过的第三方、自研、生成代码和来源未知分别记录；相似度、文件夹名和代码行数不能单独证明作者、许可证或独立贡献。
- 功能与需求到相关实现、接口和真实运行证据；截图对应版本、输入、操作及输出，不能用编辑器画面证明功能已运行。
- 授权、许可证、替换声明与构建关系的证据是否真实存在。代码包内找不到证明时列为待补，不补造声明。

可选脚本 [inventory_package.py](scripts/inventory_package.py) 生成文件摘要、大小、可解码源码的物理行数、重复内容与模块重叠情况。它不联网、不编译、不改变文件，不判断原创性、许可证或功能正确性。

```text
python -X utf8 SKILL_DIR/scripts/inventory_package.py PACKAGE_ROOT
python -X utf8 SKILL_DIR/scripts/inventory_package.py PACKAGE_ROOT --modules MODULES_JSON --source-encoding gb18030
```

占位路径换成实际值。只有已知编码时才指定；不可解码、疑似二进制、超出限制或读取中变化的源码不能当成零行。脚本口径、映射格式与限制见 [证据与统计规则](references/evidence-rules.md)。没有 Python 时使用现有统计工具，并保留相同的口径说明。

## 更新材料

优先原位更新用户指定文件或另存约定输出，保留有效结构与用户修改。数字、路径、组件状态和证据入口随实际包更新；历史材料不能伪装成本次实测。

对外交付使用包内相对路径及受审版本行号；内部定位可保留实际路径。行号会随版本变化，应绑定文件摘要或提交，不能从旧截图直接抄到新代码。

模块范围不明确时可以填写已核实部分，并给缺项清单。按用途采用 [材料与证据模板](references/material-template.md)，不要为了表格完整填估算数。Word／PDF 等视觉排版使用适用的文档工具，内容核对与导出检查分开。

## 核对最终交付

检查汇总与明细口径一致，模块重复没有直接累加；截图、路径、行号、摘要和实际送出的包对应。只对真实执行过的检查给出结果，模拟或静态核对不得写成完整功能验收。

交付实际可打开文件，说明范围、统计口径、主要更正和缺证项。若材料要求与事实冲突，指出具体冲突并提出可核实的更正或补证路径，不制造冗余代码、隐藏依赖或改写未发生的记录。
