# 证据与统计规则

## 文件盘点脚本

需要 Python 3.10+，仅使用标准库。输入是已经确定的交付目录，不自动解压、运行或修改包。输出 JSON 到标准输出；不要将带有私有路径的盘点结果自动上传。

默认排除版本控制、依赖与缓存目录，并跳过链接；明确记录排除项。`.env`、`.env.*` 以及常见私钥／证书容器文件默认不读取。排除项不代表交付包安全或依赖完整，具体范围仍需按用途核实。

每个常规文件记录相对路径、字节数、SHA256、读取中是否变化。约定扩展名的源码按解码后的物理行统计，包含空行与注释；空文件为零行，末尾无换行的最后一行计一行。优先识别 UTF BOM，否则使用明确的 `--source-encoding`，默认 UTF-8。

不可解码、含 NUL 或大于 16 MiB 的源码保留行数未知；不猜测 ANSI 编码。非源码文件不报告代码行数。脚本不能识别所有生成代码或嵌入式语言，语言／角色分类需另外核实。

默认最多处理 20000 个文件、20000 个目录，可用 `--max-files` 和 `--max-directories` 指定更大的明确范围。达到预算、读取失败或文件变化会产生不完整标记；输出部分结果，退出码为 2。源码行数未知也返回 2，不能把已知部分当完整总数。成功返回 0 仅表示当前约定范围内的盘点完成。

## 模块映射

映射由当前任务核实后提供，脚本不凭文件夹名判断归属。`paths` 和 `exclude_paths` 使用包内相对路径前缀，可指向文件或目录；`.` 表示包内全部。不是 glob 模式。绝对路径与 `..` 被拒绝。

```json
{
  "modules": [
    {"id": "core", "paths": ["src/core", "solver"], "exclude_paths": ["solver/vendor"], "origin_claim": "待核实", "evidence_refs": []},
    {"id": "shared", "paths": ["src/common"], "origin_claim": "资料中的声明", "evidence_refs": ["docs/source-note.md"]}
  ]
}
```

`origin_claim` 和 `evidence_refs` 只是任务提供的声明与线索，脚本原样标识为未经验证，不将其转成自主性判断。模块可以重叠，汇总按路径集合并集；每个模块的大小和行数不可直接相加。

按内容去重的字节数与行数是另一种诊断口径。相同内容的多个文件仍可能是有效的不同交付路径，也可能重复打包；摘要相同不证明是谁编写的。

## 来源与功能证据

| 证据 | 支持范围 |
|---|---|
| SHA256 | 对应文件字节身份 |
| 文件或模块统计 | 已声明范围与口径内的数量 |
| 开源头、许可证与来源记录 | 相应部分的来源线索，需核对适用范围 |
| 相似度结果 | 工具与阈值下的匹配线索，不能直接当贡献结论 |
| Git 历史与设计记录 | 记录涉及的改动和过程，不能补写未发生历史 |
| 运行与算例证据 | 对应版本、输入和指标的实际行为 |

汇总比例必须有可解释的分子、分母、分类依据和未知量。范围不全时报告可核实部分，不为了达到目标值调整代码量或来源标签。
