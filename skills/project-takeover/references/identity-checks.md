# 版本与运行核对

遇到多副本、多配置、桌面 EXE、本机与云端并存，或文档与实际运行矛盾时读取。以下为核对方法，具体命令按平台及本轮授权调整。

## Git 与工作树

在真实仓库路径运行只读命令；不要把当前聊天目录当成项目仓库。

```text
git --no-optional-locks -C REPO rev-parse --show-toplevel
git --no-optional-locks -C REPO rev-parse HEAD
git --no-optional-locks -C REPO branch --show-current
git --no-optional-locks -C REPO status --short
git --no-optional-locks -C REPO diff --name-status
git --no-optional-locks -C REPO diff --cached --name-status
git --no-optional-locks -C REPO worktree list --porcelain
```

分支名为空时核实是否 detached HEAD；无提交的初始仓库不填造 SHA。提交祖先关系与文件差异需要实际检查，不能按分支名字判断新旧。

本地 `origin/main` 等引用只代表本地缓存。需要查询实时远端时，优先已有连接器；命令行可用现有认证 `git ls-remote`，不要在参数里拼 token。查询失败写“远端未核实”，不推断仓库不存在。

盘点脚本为减少副作用设置 `GIT_OPTIONAL_LOCKS=0`，不读 diff 内容，不输出远端地址，不联网。状态采用 `--untracked-files=normal --ignore-submodules=all`：未跟踪目录可能折叠，子模块内容未审阅。子模块 `.git` 入口即便被发现，也需要单独核查；不能把扫描结果当完整依赖审计。

退出码 0 表示所访问目标未发生读取错误，不代表扫描完整或交接完成；2 表示输入缺失、Git 不可用或部分读取失败，JSON 中仍保留可取得的结果。`permission_denied`、`git_ownership_restriction` 等诊断必须按宿主权限机制处理，不通过添加全局 `safe.directory=*` 或换工具绕过。深度、目录预算和排除规则造成的未覆盖范围另行记录。

## 源码到构建物

最有用的证据是同一次构建记录中的源码 SHA、工作区状态、构建配置与输出摘要；脏工作区构建还需要能识别其差异的记录。仅有版本号通常不足以唯一定位源码。

桌面项目额外核对：

- 目标项目与配置，例如解决方案里的不同可执行项目、Debug／Release、x64／x86；名称相似不代表同一个目标。
- 当前进程启动路径、快捷方式目标、安装目录和最近交付目录；检查的是用户实际打开的那个 EXE。
- DLL、资源、配置与求解器的真实加载位置。工作目录、PATH 和 post-build 复制步骤可能让新 EXE 使用旧组件。
- 重编译前确认正在运行的程序与未保存工作，不强制终止；未经授权不重新打包替换原交付物。

Windows 可定向查询指定进程的 Id、Path、StartTime、MainWindowTitle，指定文件的 VersionInfo 和 SHA256，以及指定服务的启动文件或指定端口的监听进程。避免批量输出所有进程命令行，参数可能携带凭据。

重新解压启动只能证明该环境下的行为；未经独立环境验证，不扩大为“任意新电脑可运行”。

## 源码到云端

先识别环境：本地开发、局域网、测试、试用、正式、会员服务等可以独立部署。记录地址的业务职责及证据，不把同域名、相似页面或共享后端推断成同一版本。

优先核对已授权访问的版本接口、部署记录、镜像摘要或服务启动配置。实例实际报告的信息与历史文档分列。若只有网站可访问而没有版本证据，写“入口可访问，运行提交未核实”。

GitHub 的提交、CI 通过、发布包、部署成功以及真实业务验收是不同事实。跨服务接口版本需要分别映射。只有历史云部署文档时，注明记录日期与本次未登录服务器核实。

## 数据与恢复

记录数据路径和配置入口，避免输出秘密值或完整记录。相对数据库路径需结合服务的实际工作目录解析；否则容易把新建空库误认成原库丢失。

不要以建立新默认管理员、导入样例库、运行迁移或替换配置来掩盖接手缺项。确实需要恢复运行时，先判断这些动作是否在当前授权范围内，再保护相关数据并实施。

恢复演练应记录输入备份、目标隔离环境、执行结果和一致性核对；只有备份文件时写“存在备份，恢复未验证”。

## 常见判断

| 观察 | 合理结论与下一步 |
|---|---|
| 容器目录无 Git，两个子目录各有 `.git` | 两个独立仓库，分别记录版本与状态 |
| 同 SHA 的两个副本，一份有改动 | 提交基线相同，当前文件树未证实相同；核对差异和正式接续位置 |
| EXE 更新较晚，构建配置不明 | 只知道文件时间；从构建记录、进程路径和配置确认身份 |
| 本地测试通过，云版本未知 | 本地验证成立；部署对应关系仍待核实 |
| 旧文档说完成，当前测试失败 | 分列历史声明、本次失败和影响，继续定位，不能沿用“完成”状态 |
| 用户明确说继续修复 | 最小盘点后实施，不重复停在待确认计划 |
