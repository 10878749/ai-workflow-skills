# 调研与评估规则

在需要比较候选、核实可靠性、处理许可差异或决定 Fork 时读取。围绕本次使用深度取证，不把每次选库变成供应链审计。

## 搜索应当消除哪类不确定性

1. **现状**：现有项目是否已依赖同类能力，标准库或框架自带能力能否满足。
2. **候选身份**：官方文档链接到的仓库、包名称、当前推荐安装入口是否一致；搜索结果是否只是镜像、样例或停更封装。
3. **关键能力**：官方 API、相关实现、测试和限制是否支持本项目的核心路径。
4. **可信程度**：采用证据、维护与缺陷处理是否支持“值得作为基础”的判断。
5. **接入代价**：在本项目真实条件下是否比自建更省事、更可维护。

优先缩小未知项最大的方向。搜索失败、页面受限或工具只返回部分结果时记录范围，不扩大成“无可用项目”。决定涉及重要限制时，查看原始文件和版本记录，不只读搜索摘要。

## 候选资格与比较维度

硬条件来自用户和当前任务，不预设所有项目必须支持 Windows、商用、离线或某种许可证。

| 维度 | 应核对的证据 | 常见误判 |
| --- | --- | --- |
| 核心功能与边界 | 官方接口、源码、相关测试、代表性输入的试验 | README 宣称支持就认为完整可用 |
| 环境与成本 | 版本矩阵、依赖清单、构建与部署说明、实际资源需求 | 本机 Demo 可运行就认为目标设备可用 |
| 真实采用 | 下游项目的依赖文件／代码、可核查使用案例，注明场景和所用版本 | Star、下载量、官网 Logo 等于生产验证 |
| 维护 | 支持策略、发布／修复记录、相关 Issue／PR 的处理质量 | 只看最近提交或 Issue 数量；无 Issue 就认为无问题 |
| 测试与安全 | 相关测试与运行状态、目标版本公告和修复范围，必要时的安全工具结果 | CI 徽章／总分保证业务正确；搜索不到漏洞就称安全 |
| 许可证与归属 | 精确版本 LICENSE、文件头、NOTICE、第三方目录和所用资产条款 | 仓库公开就能任意商用、复制或再分发 |
| 可扩展和退出 | 文档化扩展点、数据导出、协议、升级策略、Fork 差异 | 改核心比适配器快，所以长期成本也低 |

判断为未知时写出需要哪份证据或哪个实验才能改变结论。功能或许可等硬条件有实质未知时，不包装为“可直接采用”。使用量证据不足但适配度好的小项目可以进入试验，标明采用证据弱和相应验证责任，不因规模小一票否决。

## “大量使用并证明可靠”如何表达

分别回答：谁在使用、以什么方式使用、是不是当前功能、能支持多强的结论。

- 最有用的是可以追溯的真实下游代码／依赖和使用反馈，且与目标平台、规模、功能接近。
- 包下载量可能包含 CI、镜像和重复安装，仓库 dependents 也有统计覆盖限制。记录数据来源与日期，称为采用信号，不换算成独立用户。
- 自述案例和官网客户墙标为上游自述；有外部材料才能提高独立性，不把多个转载算多份证据。
- 小而稳定、协议成熟的项目，发布间隔长可能正常。确认仍可构建、维护状态和兼容性；不为“活跃”优先追逐频繁破坏兼容的新项目。
- 可靠性结论限定用途。例如“发现多项 Web 编辑器集成；本机试验验证了当前输入下的撤销”，不写“行业验证，绝对可靠”。

## 许可证检查到实际复用内容

把本次动作写清：只阅读、作为依赖、复制代码、修改／派生、打包交付，还是提供网络服务。然后读取目标版本及相关文件的实际条款，记录署名、许可文本、NOTICE、源码提供等与当前动作有关的要求。

仓库公开、GitHub 可 Fork 或自动识别的许可标签，不能替代许可内容。无许可证或权限不清时，不把代码复制、派生或分发认定为已获授权；优先找许可明确的替代。需要时仅借鉴非受保护的一般思路，并独立实现，不能靠改变量名规避来源问题。

区分代码、字体／图片／模型权重／数据集、示例和第三方依赖，检查实际使用部分，避免根目录一个 MIT 标签覆盖全部的假设。GPL／AGPL 等条款的影响取决于版本、组合和使用方式，不简单写成“不能商用”。有决定性且无法确认的义务时，说明具体待确认点，相关路径保持暂定。

## 试验应决定采用还是退出

选择能最早淘汰错误基础的小实验，而非只运行 Hello World。例子：桌面软件先检查目标系统和接口可用性；文档导出先检查复杂内容及目标终端效果；几何／数值组件先检查代表性输入与结果约定；需断网使用的功能先检查真实离线路径。

将“检查过”“实际运行成功”“失败”“未运行”分开。环境问题导致不能运行时保留原因，不归为功能失败，也不归为成功。新事实触及原来的硬条件或成本预期，就更新决定；替代方案连续遇到同一外部阻碍时，说明阻碍并交付当前证据，避免无限重试。

## 可参考的原始资料

以下是方法参考，不是永久有效的候选清单。选型时仍需核对当前官方资料与目标版本。

- [GitHub：Licensing a repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)：公开仓库与可复用授权的区别、许可证定位和识别边界。
- [OpenSSF Scorecard](https://scorecard.dev/)：开源项目安全实践的自动检查；相关结果可作为局部风险信号，不能替代本项目的适配与功能验证。
