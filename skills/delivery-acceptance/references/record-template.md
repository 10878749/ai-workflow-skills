# 按需裁剪的验收记录

优先更新已有验收入口。小任务可直接用几句话说明，不强制创建文档或 JSON。

```text
用途：使用者、环境、要完成的动作
对象：实际文件／包／网址、版本或摘要、核实时间
完成条件：用户要求与暂定假设分开

路径：输入 → 操作 → 最终结果位置
环境／前提：设备、账号、数据、真实或模拟服务
预期：能直接观察或核对的结果
本次观察：实际结果，不填计划
状态：通过／失败／阻断／未执行
证据：文件、日志、请求标识或截图入口
覆盖限制：该证据尚不能证明什么

保留行为与相关失败路径：按本次影响选择
首次失败、修复与复测：分别记录
结论：满足用途／部分满足／尚不能判断／未满足
下一动作：具体入口、前提与完成判据
```

如果不同设备或版本结果不同，分条记录。不要把一次桌面浏览器检查合并成 Android、iOS 和小程序均通过。
