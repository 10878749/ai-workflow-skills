# 按用途选择检查

只读相关一类。下面是选择检查的依据，不是每轮必须填满的清单。

## 网页与小程序

从使用者实际入口完成一条完整路径，检查导航、返回后的筛选／滚动状态、输入与结果，以及本次变化会影响的原功能。显示与触摸问题应在相关屏幕或设备条件下观察。

“保存成功”要追到浏览器下载、设备相册或服务器记录；模拟器可能只模拟调用，不能据此证明手机相册已有文件。任务卡、双面组件或多种布局应保留受影响的状态覆盖。

异步任务检查最终状态而非只看 HTTP 200；刷新、失败和中断后是否保留、恢复或退还，应按产品约定验证。不要为了演示重复触发真实付费任务。

真实模型与规则／缓存回退要分开。优先用请求标识、供应商响应、已有账单或追踪记录对应一次调用；网页出现一段答案不能证明调用了指定模型。Mock、服务端测试和真实调用各自只支持其实际范围。

发布版本需核对域名、访问权限和运行身份。用户目标是独立展示时，还要明确是否依赖开发电脑、同一局域网、特定账号或外部服务。真机、平台审核与微信内环境无法覆盖时如实记录。

## 桌面软件与交付包

核对实际 EXE、目标构建配置、架构、配套 DLL／资源和启动目录。已授权时从独立解压或安装位置运行，避免依赖开发目录的 PATH、配置或资源。

看见窗口只证明启动到该位置。验收一个真实目标操作，并检查输入加载、生成文件、求解器／插件调用和可打开结果。专业数值正确性需要已知算例、可靠比较指标与容差，不能从编译成功推出。

只在请求涵盖时检查重装、卸载、数据保留和恢复。事先识别未保存内容与用户数据，不强行结束程序，也不把本机移位测试扩张成“任意干净电脑可用”。

高 DPI、字体和弹窗问题应在相关显示比例下观察；不要只改字体而遗漏控件位置、截断和窗口尺寸。

## 设计文件与文档

核对用户批准的内容与版式、页面／正反面是否齐全，以及可编辑源文件和最终导出是否对应。只改底图时，把版式与内容作为保留条件。

印刷用途核对实际尺寸、出血、安全区、字体、有效分辨率或矢量元素，以及打印方提出的格式要求。只有屏幕预览时，结论限定为预览检查；没有打印方或打样证据，不声称已获印刷验收。

文档核对数字、单位、来源、表格、分页、图片与导出。内容一致性与视觉检查分别说明；渲染器无法打开时保留限制，不能凭文件扩展名宣称可用。

## 证据层次

| 观察 | 能支持的范围 |
|---|---|
| 构建／类型检查通过 | 对应版本在该环境的构建／静态检查 |
| 模拟器调用成功 | 对应模拟环境的接口与流程 |
| 真机出现最终保存文件 | 该设备条件下的实际保存 |
| 真实供应商记录与请求对应 | 该次真实外部调用 |
| 已知算例符合有效容差 | 对应算例、指标和配置的专业结果 |
| 专家或交付方确认 | 其明确审阅的对象与范围 |
