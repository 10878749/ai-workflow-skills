# 接入与评测

按当前目标选择最小层次，不固定阶段数量。

| 层次 | 主要产物 | 证据边界 |
|---|---|---|
| 软件问答 | 版本化说明与引用，保留原帮助入口 | 知识覆盖不证明可操作当前工程 |
| 只读上下文 | 实际工程摘要与身份／版本 | 摘要不等于完整模型，外发范围另行核实 |
| 宿主工具 | 直接选择参数、检查、应用与回读 | 不依赖模型，可先验证确定性程序路径 |
| 模型草稿 | 真实模型输出受支持的结构与缺项 | 草稿通过不等于已执行或专业正确 |
| 受控执行 | 状态校验、修改或启动、结果查询 | 使用真实目标时才支持对应业务结论 |

把验收拆成真实输入与观察：调用了哪个旧接口、最终修改哪个对象、旧草稿是否拒绝、原帮助是否正常、重复请求产生几个任务、断连后能否找到原作业。不要仅检查提示文字或工具名称。

专业算例需要记录输入、配置、比较对象、指标及容差依据。模拟求解结果不能支持真实求解能力；无专家或基准证据时，保留专业正确性待验收。

如果已有接口不稳定，先用一个已知任务消除接口和状态不确定性。不要把 UI 自动点击接入的脆弱性隐藏在“Agent 已完成”中；对无法稳定回读的操作限制自动化范围。

正式集成还需让配置、环境和部署边界可追踪。本机工具无法被独立网页直接使用时，说明桥接的缺口；不要通过关闭鉴权或放宽跨域来让演示通过。
